> 이 페이지는 처음 클로드를 쓰는 분을 위한 기초예요. 버튼 이름과 메뉴 위치는 자주 바뀌니, **화면 표시가 다를 수 있어요.** 그럴 땐 비슷한 이름을 찾아보세요.

## 1. 클로드란 무엇이고, 어디서 쓰나요

클로드(Claude)는 Anthropic이 만든 AI 어시스턴트예요. 글로 물어보면 글로 답하고, 파일을 읽고, 문서와 웹페이지를 만들고, 컴퓨터 안의 폴더에서 직접 일도 해요.

쓰는 곳은 여러 군데예요.

- **웹**: 브라우저에서 claude.ai
- **데스크탑 앱**: 컴퓨터에 설치하는 Claude 앱 (내려받기: [claude.ai/download](https://claude.ai/download))
- **모바일 앱**: iOS·안드로이드 앱
- 그 밖에 크롬 확장 같은 것도 있어요.

같은 계정으로 로그인하면 어디서든 이어서 쓸 수 있어요. 이 강좌는 **데스크탑 앱**을 기본으로 해요.

데스크탑 앱에는 위쪽(또는 옆)에 **Chat**, **Cowork**, **Code** 탭이 있어요. 이 페이지에서 다룰 것은 Chat과 Code예요.

## 2. 챗(Chat): 물어보고, 파일 보여주고, 자료 모으기

### 질문 요령

[프롬프트 잘 쓰는 법](/skills/prompt-writing)에 자세히 있어요. 한 줄로 줄이면 이래요.

- **무엇을, 누구를 위해, 어떤 모양으로** 말해요. "블로그 글 써줘"보다 "카페 신메뉴를 알리는 200자 안내문, 부드러운 말투로"가 좋아요.
- 마음에 안 들면 처음부터 다시 쓰지 말고 **"둘째 문장을 더 짧게"**처럼 고칠 곳만 말해요.
- 주제가 바뀌면 새 대화를 열어요. 대화가 길어지면 앞 내용을 놓치기 쉬워요. ([계획 먼저, 코드는 나중에](/skills/plan-mode-and-context))

### 파일·이미지 붙이기

채팅창 왼쪽 아래의 **+** 버튼에서 파일이나 사진을 추가하거나, 파일을 채팅창에 끌어다 놓거나, 클립보드의 이미지를 붙여넣을 수 있어요. 공식 안내 기준으로 PDF·DOCX·CSV·TXT 같은 문서와 JPEG·PNG·GIF·WebP 이미지를 읽어요. 크기와 개수에는 한도가 있어요. 화면 캡처를 붙이는 방법은 [이미지·파일 다루기](/skills/images-and-files)에 있어요.

### 프로젝트(Projects): 자료 모아 두기

같은 일을 계속 한다면 **프로젝트**를 만들어요. 프로젝트에는 참고 파일(지식)과 "이렇게 답해줘"라는 안내(프로젝트 지침)를 넣어 두고, 그 프로젝트 안에서 대화할 때마다 클로드가 그것을 참고해요. 예를 들어 "우리 가게 소개 + 말투 규칙"을 넣어 두면 매번 설명하지 않아도 돼요. 만드는 곳은 claude.ai의 Projects 메뉴예요.

## 3. 아티팩트(Artifacts): 옆 화면에서 바로 보고 고쳐요

문서, 웹페이지, 작은 도구 같은 **그럴듯한 결과물**을 만들면, 클로드는 대화 옆에 **별도 창**으로 그것을 열어 줘요. 대화는 왼쪽, 결과물은 오른쪽에서 동시에 볼 수 있어요.

- 종류: 문서, 슬라이드, 디자인, 코드와 작은 앱, 한 페이지짜리 웹사이트, 다이어그램 등
- 고치는 법: 대화로 "버튼을 파란색으로" 하고 시키거나, 글자를 드래그해서 **Edit with Claude**로 그 부분만 고쳐 달라고 해요. 문서·슬라이드 같은 형식은 직접 고칠 수도 있어요.
- 처음에는 **나만 볼 수 있고**, 공유 여부는 내가 정해요. (공유 방식은 요금제에 따라 달라요.)

"한 번 만들어 보고 눈으로 확인하는" 용도로 좋아요. 파일로 저장해 내 사이트에 쓰는 일은 다음 코드 탭에서 해요.

## 4. 코드(Claude Code): 내 폴더에서 일을 시켜요

Chat이 "대화"라면 Code는 **내 컴퓨터의 폴더에서 파일을 직접 만들고 고치는** 도구예요. 이 강좌의 본 무대예요. 설치와 첫 로그인은 [홈페이지 만들기 2강](/lectures/homepage/lesson-02)에서 단계별로 해요.

### 시키는 순서

1. 데스크탑 앱을 열고 로그인한 뒤 **Code** 탭을 눌러요.
2. 입력창 근처에서 **프로젝트 폴더**를 골라요. 클로드는 이 폴더 안에서 일해요.
3. 필요하면 **모델**과 **권한 모드**를 골라요. (둘 다 보내기 버튼 옆에서 바꿀 수 있어요.)
4. 하고 싶은 일을 한국어로 쓰고 Enter를 눌러요.
5. 중간에 방향이 틀리면 **정지 버튼**을 누르거나, 고칠 말을 써서 보내요.

대화(세션)마다 폴더와 기록이 따로예요.

### 권한 요청 읽는 법

기본 모드(Manual)에서는 클로드가 파일을 고치거나 명령을 실행하기 전에 **물어봐요.** 파일 수정은 무엇이 바뀌는지 비교 화면(diff)이 나오고, 수락하거나 거절할 수 있어요.

- 무엇을 바꾸는지, 어느 파일인지 **읽고** 눌러요. 읽지 않고 계속 수락하는 습관이 가장 위험해요.
- `npm install`, `git push`처럼 밖으로 영향이 가는 명령은 특히 더 신중하게요. ([승인 모드와 안전장치](/skills/permissions-and-safety))

권한 모드는 공식 안내 기준으로 대략 이래요. 이름은 버전에 따라 달라요. (예전 앱에서는 Ask permissions·Auto accept edits·Plan mode로 불렸어요.)

| 모드 | 하는 일 |
|---|---|
| Manual | 파일 수정과 명령 실행 전에 매번 물어봐요 |
| Accept edits | 파일 수정은 알아서, 다른 명령은 물어봐요 |
| Plan | 읽고 계획만 제안하고 소스는 고치지 않아요 |

그 밖에 더 자동인 모드도 있지만, 처음에는 Manual로 시작해요.

### 플랜 모드

큰 일을 시키기 전에 **Plan** 모드로 두고 "아직 고치지 말고 어떻게 할지 계획만 알려줘"라고 해 보세요. 계획을 읽고 고친 뒤에 실행하면 훨씬 덜 헤매요. 자세한 방법은 [계획 먼저, 코드는 나중에](/skills/plan-mode-and-context)에 있어요. 터미널(CLI)의 Shift+Tab 단축키는 데스크탑 앱에서는 쓰지 않고, 모드 선택 버튼을 써요.

## 5. 이 강좌의 기본 에이전트는 클로드 데스크탑이에요

이 강좌는 **Claude 데스크탑 앱의 Code 탭**을 기본 도구로 써요. 앱에서 폴더 선택, 변경 비교, 미리보기를 눈으로 확인할 수 있어서 처음 하는 분에게 편해요.

**터미널로도 할 수 있어요.** 같은 Claude Code를 터미널에서 `claude`로 실행하는 방법(CLI)도 있어요. 서버나 자동화에서는 CLI가 편해요. 둘의 차이는 [데스크탑 앱 vs CLI](/skills/desktop-app-vs-cli)에, 터미널로 진행하는 과정은 [홈페이지 만들기 (CLI)](/lectures/homepage-cli)에 있어요.

## 6. 자주 막히는 것

| 증상 | 먼저 해 볼 것 |
|---|---|
| **로그인이 안 돼요 / Code 탭에서 403·인증 오류** | 앱 메뉴에서 로그아웃 후 다시 로그인해요. Code 탭은 유료 구독이 필요하다고 안내돼 있으니 구독 상태도 확인해요. 그래도 안 되면 앱을 완전히 종료했다가 다시 열어요. |
| **"한도에 도달했어요"** | 사용량 한도는 일정 시간이 지나면 풀려요. 기다리거나 요금제를 확인해요. 대화가 너무 길어서 생기는 **길이 한도**는 새 대화를 열면 돼요. 긴 대화일수록, 큰 파일을 많이 붙일수록 빨리 줄어요. |
| **권한 요청이 계속 떠요** | 정상이에요. 안전한 읽기 명령만 "항상 허용"하는 방법은 [승인 모드와 안전장치](/skills/permissions-and-safety)에 있어요. 끄는 것은 되돌리기(Git)에 익숙해진 뒤에요. |
| **앱이 이상해요 / 새 기능이 안 보여요** | 앱을 업데이트하고 다시 시작해요. macOS·Windows에서는 실행할 때 자동으로 업데이트된다고 안내돼 있어요. 메뉴에서 업데이트 확인도 할 수 있어요. |
| **파일이 안 보여요** | 선택한 **프로젝트 폴더 안**의 파일만 보여요. 폴더를 제대로 골랐는지, 파일이 그 안에 있는지 확인해요. 클로드에게 "지금 폴더의 파일 목록을 보여줘"라고 시켜도 돼요. 첨부할 때는 + 버튼으로 올려요. |
| **에러가 나요** | [에러 디버깅하는 법](/skills/error-debugging), [짧은 팁](/tips)을 봐요. |
