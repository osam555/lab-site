> **화면 표시가 다를 수 있어요.** 기능과 메뉴 이름은 바뀔 수 있어요. 기본 사용법은 [클로드 기초](/basics/claude-basics)에 있어요.

## 1. 아티팩트로 "한 페이지 홈페이지" 먼저 만들어 봐요

공식 도움말 설명으로 아티팩트(Artifacts)는 클로드가 만들어 주는 **남에게 보여 줄 만한 결과물**이에요. 문서, 슬라이드, 디자인(목업·시안·랜딩 페이지), 코드와 **한 페이지짜리 웹사이트**, 다이어그램·대시보드 같은 것이 있어요. 대화 옆에 별도 창으로 열려서, 만들면서 바로 눈으로 볼 수 있어요.

**순서**

1. 클로드 채팅에서 말해요. 예: "동네 카페 소개 한 페이지 웹사이트를 만들어줘. 메뉴 3개, 영업시간, 위치 안내가 들어가게. 부드러운 말투로."
2. 오른쪽에 열린 결과를 보고 고칠 곳을 말해요. "제목을 더 크게", "색을 따뜻하게". 글자를 드래그해서 그 부분만 고치게 할 수도 있어요.
3. 마음에 들면 공유해요. 공식 안내로 아티팩트는 **처음엔 나만 볼 수 있고**, **공유 링크로 게시**할 수 있어요. 누가 어떤 방식으로 공유할 수 있는지는 **요금제와 설정에 따라 달라요.** 내 화면에서 공유 메뉴가 보이는지 먼저 확인해요.
4. 링크를 보내 남에게 보여 줘요. 공개 범위를 읽고 나서, 개인정보(전화번호·주소)가 들어 있다면 정말 공개해도 되는지 확인해요.

이 방법은 **명함 대신 쓰는 소개 페이지, 행사 안내, 시안 공유**처럼 가볍게 보여 줄 때 좋아요. 내 도메인을 붙이거나 계속 고쳐 가며 운영하려면 아래 흐름으로 옮겨요.

## 2. 정식 홈페이지가 필요해지면: Code 탭 → 깃허브 → 버셀

아티팩트는 "빨리 만들어서 보여 주기"에 강해요. 아래가 필요하면 Code 탭으로 옮겨요.

- 내 주소(도메인)를 쓰고 싶다
- 여러 페이지, 문의 폼, 계속 이어지는 수정과 기록이 필요하다
- 파일을 내 폴더에 두고 되돌리기까지 하고 싶다

**옮기는 흐름**: 아티팩트 내용(HTML)을 클로드에게 "이 페이지를 내 프로젝트 폴더의 파일로 저장해줘"라고 시켜요 → [깃으로 저장](/basics/git-basics) → [깃허브에 올리기](/basics/github-basics) → [버셀 연결과 배포](/basics/git-vercel-deploy) → 필요하면 [도메인 연결](/basics/domain-basics). 전체 실습은 [홈페이지 만들기](/lectures/homepage)에 있어요. 아티팩트에서 코드를 어떻게 꺼내는지는 화면마다 달라서, 안 보이면 클로드에게 코드를 통째로 달라고 하면 돼요.

## 3. 그 밖의 쓰임

- **문서·슬라이드·디자인 아티팩트**: 보고서, 발표 자료(공식 안내로 PowerPoint·PDF로 내보내기 가능), 화면 시안을 대화로 만들어요. 템플릿은 요금제에 따라 쓸 수 있는지가 달라요.
- **프로젝트(Projects)**: 같은 일을 반복한다면 프로젝트에 참고 자료(지식)와 "이렇게 답해줘"(지침)를 넣어 두세요. 그 프로젝트 안의 대화마다 클로드가 참고해요. 단, **프로젝트 안의 다른 대화 내용이 자동으로 공유되지는 않아요.** 남기고 싶은 것은 자료에 추가해요.
- **이미지·파일 읽히기**: 채팅의 **+** 버튼이나 끌어다 놓기로 PDF·문서·표·이미지를 주고 "요약해줘", "표로 정리해줘", "이 화면 캡처에서 에러를 읽어줘"라고 해요. 크기·개수 한도가 있어요. ([이미지·파일 다루기](/skills/images-and-files))

## 4. 터미널로도 할 수 있어요

위의 아티팩트·프로젝트는 채팅 기능이라 터미널이 필요 없어요. 정식 홈페이지로 옮긴 뒤의 깃·배포만 터미널로도 할 수 있어요. ([깃 기초](/basics/git-basics))
