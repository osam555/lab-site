> **화면 표시가 다를 수 있어요.** 공식 문서에서 확인한 범위만 적었어요(확인일 2026-10-06). **버셀(Vercel)로 배포하는 단계는 앤티그래비티 공식 문서에 없어서** 기존 기초지식 페이지로 이어요.

## 순서 한눈에

| 단계 | 어디서 | 설명 |
|---|---|---|
| 1 저장(커밋) | 앤티그래비티 2.0 **VCS 패널** | 공식 문서에 있어요 |
| 2 깃허브로 보내기(푸시) | 앤티그래비티 2.0 **VCS 패널** | 공식 문서에 있어요 |
| 3 깃허브 저장소 만들기·계정 | 깃허브 웹사이트 | [깃허브 기초](/basics/github-basics) |
| 4 버셀로 공개 | 버셀 웹사이트 | [깃-버셀 연동과 배포](/basics/git-vercel-deploy) |

용어를 먼저 풀어 둘게요.

- **커밋(commit)**: 지금 상태를 "저장 지점"으로 남기는 것. 게임의 세이브예요.
- **푸시(push)**: 내 컴퓨터의 저장 지점을 깃허브(인터넷 저장소)로 올려 보내는 것.
- **깃(Git)**: 저장 지점들을 관리하는 도구. 자세한 건 [깃 기초](/basics/git-basics)에 있어요.

## 1. 앤티그래비티에서 저장하기

공식 문서에 따르면 2.0의 사이드바에는 **깃 중심의 버전 관리(VCS) 패널**이 있고, 버전 관리 버튼으로 열어요. 여기서 할 수 있는 일이에요.

- **변경 비교 보기**: 저장 전 변경 전체(uncommitted), 현재 브랜치의 변경, 에이전트가 고친 부분
- **파일 단위 작업**: 스테이지(저장 대상에 담기), 언스테이지, 버리기
- **Commit(커밋)**: 로컬에 저장 지점을 만들어요. **커밋 메시지를 자동으로 만들어 주는 옵션**도 있어요.
- **Push(푸시)**: 현재 브랜치의 커밋을 원격 저장소로 보내요.

> 내 폴더가 깃 저장소가 아니면 이 기능을 쓸 수 없을 수 있어요. 공식 문서는 폴더 종류를 "깃이 설정되지 않은 일반 폴더(Local folders)"와 "깃 저장소(Local Git checkout)"로 나눠요. 아직 깃을 안 썼다면 에이전트에게 "이 폴더를 깃 저장소로 만들어줘. 만들기 전에 어떤 명령을 쓸지 먼저 알려줘"라고 시켜 보세요.

**읽어 보고 누르는 규칙**: 푸시는 인터넷에 올리는 일이에요. 올리기 전에 변경 비교에서 **비밀번호·API 키·개인 정보가 든 파일**이 없는지 꼭 확인하세요. ([안전과 비용](/basics/vibe-safety-money))

## 2. 터미널은 사이드바에 있어요

공식 문서에 따르면 2.0에는 **통합 터미널(integrated terminal)** 이 있고, 사이드바의 터미널 버튼이나 단축키 **Ctrl/Cmd + `** 로 열어요. 용어: 터미널은 글자로 컴퓨터에 명령하는 창이에요. 깃 명령을 직접 쓸 수도 있지만, 초보는 에이전트에게 맡기고 **명령을 읽고 허용**하는 쪽이 안전해요.

## 3. 깃허브와 버셀

이 두 단계는 앤티그래비티가 아니라 각 웹사이트에서 해요. 클로드 데스크탑 과정과 똑같아요.

1. 깃허브에 빈 저장소를 만든다 → [깃허브 기초](/basics/github-basics)
2. 앤티그래비티에서 푸시한다 (이 강의 1번)
3. 버셀에서 그 저장소를 가져온다 → [깃-버셀 연동과 배포](/basics/git-vercel-deploy)
4. 도메인은 나중에 → [도메인 기초](/basics/domain-basics)

배포가 실패하면 [배포 문제 해결](/basics/deploy-troubleshooting)을 보세요.

::: practice
- [ ] `my-site`가 깃 저장소인지 확인했다 (아니면 에이전트에게 만들게 했다)
- [ ] VCS 패널을 열어 변경된 파일 목록을 봤다
- [ ] 변경 비교를 읽고 비밀번호·키 같은 것이 없음을 확인했다
- [ ] Commit으로 저장 지점을 만들었다
- [ ] (선택) 깃허브 저장소를 만들어 Push까지 했다
- [ ] (선택) 버셀에 가져와 배포 주소를 열어 봤다
:::
