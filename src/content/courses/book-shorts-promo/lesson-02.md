## 원고가 있어야 뽑을 수 있어요

클로드는 파일을 읽을 수 있어요. 이 사이트의 [클로드 기초](/basics/claude-basics)에도 PDF·DOCX·TXT 같은 문서를 읽는다고 나와 있어요(크기와 개수에는 한도가 있어요). 다만 책 한 권 전체를 한 번에 읽히면 길고 느려져요. 그래서 **장 단위로 나눠 두는 것**이 좋아요.

## 폴더 구조

```
book-shorts/
├─ CLAUDE.md          규칙 파일
├─ book-info.md       1강에서 만든 책 정보
├─ manuscript/        원고 (장별 파일)
│   ├─ ch01.md
│   ├─ ch02.md
│   └─ ...
├─ picks/             쇼츠 후보와 확정 대본
├─ cards/  voice/  out/   (2부에서 생겨요)
```

**원고가 md(마크다운) 파일이면** 그대로 `manuscript/`에 넣어요. **PDF 한 권이면** 통째로 두지 말고 클로드에게 장별로 나눠 달라고 해요.

> `manuscript/book.pdf`가 내 책 전체 원고야. 장 제목을 기준으로 `manuscript/ch01.md`, `ch02.md` … 처럼 장별 텍스트 파일로 나눠줘. 원문을 요약하거나 고치지 말고 그대로 옮겨. 끝나면 장 개수와 각 파일의 글자 수를 표로 보여줘.

PDF에서 글자를 뽑을 때 표나 각주가 깨질 수 있어요. 한두 장은 원본과 눈으로 비교해서 문장이 빠지지 않았는지 확인해요. 스캔한 PDF라서 글자 선택이 안 되는 경우에는 [이미지·파일 다루기](/skills/images-and-files)의 PDF 변환 안내를 먼저 봐요.

## 규칙 파일 만들기

CLAUDE.md는 클로드가 이 폴더에서 일할 때마다 먼저 읽는 규칙 메모예요([규칙 파일 깊이 보기](/skills/rules-file-deep-dive)). 책 홍보에서는 이 네 가지가 중요해요.

> 이 폴더 규칙 파일 `CLAUDE.md`를 만들어줘. 내용은 이래.
> 1. 이 폴더의 `manuscript/`는 내가 직접 쓴 내 책 원고다. 다른 사람의 책이나 글은 발췌하지 않는다.
> 2. 쇼츠에 쓰는 문장은 원고 문장을 그대로 인용하거나, 바꾼 곳은 표시한다. 원고에 없는 사실이나 숫자를 지어내지 않는다.
> 3. "조회수 보장", "효과 보장", "무조건" 같은 표현은 쓰지 않는다.
> 4. 영상 업로드, 글 게시, 메시지 발송은 내가 확인한 뒤에 한다. 비밀번호와 API 키는 채팅에 쓰지 않는다.

비밀번호나 키는 `.env` 같은 파일에 두고 깃에 올리지 않아요. 이유와 방법은 [안전·비용·계정](/basics/vibe-safety-money)에 있어요.

## 첫 커밋

작업을 되돌릴 수 있게 지금 상태를 저장해 둬요(커밋은 "저장 시점 표시"예요, [깃 기초](/basics/git-basics)).

> 이 폴더를 깃 저장소로 만들고 "책 쇼츠 프로젝트 시작" 메시지로 첫 커밋을 해줘. 단, 원고 파일 `manuscript/`는 `.gitignore`에 넣어서 올라가지 않게 해줘.

원고를 인터넷 저장소에 올리면 출간 전 내용이 공개될 수 있어서, 원고는 제외해요. 권한 요청 창의 명령(`git init`, `git commit` 등)을 읽고 수락해요. 터미널로도 할 수 있어요. `git init`, `git add .`, `git commit -m "..."` 순서예요.

::: practice
- [ ] `manuscript/` 안에 장별 파일이 만들어졌고, 한 장을 열어 원문과 비교해 문장이 빠지지 않았다
- [ ] `CLAUDE.md`를 직접 열어 "내 책만", "지어내지 않는다", "내가 확인한 뒤에" 세 줄이 있는지 확인했다
- [ ] `.gitignore`에 `manuscript/`와 `.env`가 들어 있다
- [ ] 첫 커밋이 만들어졌다
:::

## 오늘의 체크리스트

- [ ] 원고가 장별 파일로 정리되어 있다
- [ ] 규칙 파일에 저작권·보장 금지·확인 후 발송 규칙이 있다
- [ ] 원고가 깃에 올라가지 않게 제외했다
