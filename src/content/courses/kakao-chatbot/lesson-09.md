## 입력이 곧바로 지식이 되면 안 돼요

운영하다 보면 방장이 "이건 이렇게 답해야 해"를 바로 알려 주고 싶어져요. 하지만 **방에서 쓴 말이 곧바로 봇의 답이 되면** 이름을 흉내 낸 누군가가 봇에게 거짓을 가르칠 수 있어요. 그래서 이 강의 핵심 원칙은 이거예요.

> **사용자 입력이 곧바로 지식이 되지 않게, 사람의 승인 단계를 둔다.**

## 흐름

```
방장이 방에서 "@도우미 기억: 내용"
  → 서버의 승인 대기함에 쌓임(답에는 쓰이지 않음)
  → 내가 내 컴퓨터에서 목록을 보고 승인/반려
  → 승인하면 정정표 항목 초안이 만들어짐
  → 빌드 검사·평가를 통과하면 내가 배포 → 그제서야 답에 반영
```

접수된 내용은 **승인 전까지 어떤 답변에도 쓰이지 않아요.** 이름이 위조돼서 접수되어도 라이브 답은 바뀌지 않으니, 승인 단계가 마지막 방어선이에요.

## 안전하게 만드는 규칙

- **방장만** 가르칠 수 있어요. 비방장에게는 "방장님만 가르칠 수 있어요" 정도로만 답해요.
- 글자 수를 제한하고 **개인정보 패턴이 있으면 거절**해요.
- 하루 접수 건수를 제한해요.
- (선택) **확인 코드**: 매일 바뀌는 코드를 명령에 붙이면 서버가 검증해서 이름 위조와 구분해요. 코드는 폰 모듈이 모르게 서버가 계산하고, 내 컴퓨터 화면에서만 보여요. 틀린 코드가 연속되면 한동안 잠가요.
- 방장 표시 이름이 같은 사람이 흉내 낼 수 있다는 한계는 **승인 단계**로 막아요.
- 접수 목록 조회에는 **번호와 상태만** 보여 주고 내용은 방에 노출하지 않아요.

## 따라하기

> 방에서 방장이 `@도우미 기억: 내용`으로 가르치면 서버 승인 대기함에 쌓는 API와 폰 스크립트 명령을 만들어줘. 방장만 허용, 300자 제한, 전화·이메일·계좌 패턴 거절, 하루 접수 한도, 접수 번호 회신을 포함해. 접수된 내용은 승인 전에는 `/api/ask`가 절대 읽지 않게 분리해줘. 내 컴퓨터에서 `list`, `approve N`, `reject N`을 할 수 있는 스크립트도 만들어. 승인하면 6강 정정표 항목 **초안**만 만들고, 빌드·배포는 내가 직접 하게 해줘.

터미널로도 할 수 있어요. 승인 스크립트는 터미널에서 직접 실행하는 도구예요.

## 시험 시나리오

1. 방장 계정으로 `기억:`을 보낸다 → 접수 번호가 온다
2. **다른 계정으로 같은 명령** → 거절된다
3. 접수 직후 같은 주제를 물어본다 → **답은 아직 바뀌지 않는다**
4. 승인·정정표 반영·배포 후 → 표현을 바꿔 물으면 새 답이 나온다

::: practice
- [ ] 방장 계정으로 가르친 내용이 대기함에 쌓였고 번호를 받았다
- [ ] 비방장 계정의 명령이 거절되는 것을 확인했다
- [ ] 접수한 내용이 승인 전에는 답에 쓰이지 않는 것을 확인했다
- [ ] 승인 → 정정표 초안 → 검사 → 배포 흐름을 한 번 끝까지 해 보았다
:::
