## 누가 쓰나요
DM으로 케이크·꽃다발·수제 반찬 주문을 받는 1인 사업자.

## 어떤 문제
DM은 주문이 섞이고, 픽업 날짜를 놓치고, 같은 질문에 매번 답한다.

## 핵심 기능 3개
1. 고객용 주문 폼: 상품 선택 + 수량 + 픽업 날짜 + 연락처 → 접수 번호 발급
2. 사장님용 관리 화면: 날짜별 주문 목록, 상태 변경(접수 → 준비 → 완료)
3. 접수/완료 시 고객에게 이메일 자동 발송

## 성공 기준
한 달간 DM 대신 이 폼으로 주문의 80%를 받는다.

## 안 만들 것
결제, 재고, 쿠폰, 리뷰, 다중 매장.

## 조각 예시
- [ ] 상품 목록 (products 테이블, 관리 화면에서 등록)
- [ ] 주문 폼 (화면만) → orders 테이블 저장
- [ ] 접수 번호 생성 + 완료 화면
- [ ] 사장님 로그인 (사장님 계정 하나만 허용)
- [ ] 관리 화면: 날짜 필터 + 상태 변경
- [ ] 이메일 발송 서버 라우트 (Resend 등)
- [ ] 픽업 가능 날짜 제한 (휴무일)
- [ ] 폰 최적화 (고객은 100% 폰)

## 왜 중급인가
고객(로그인 없음)과 사장님(로그인)의 권한이 다르고, RLS를 "사장님만 읽기, 누구나 insert"로 설계해야 합니다. 이메일 API도 하나 더 붙습니다.
