## 왜 용어부터 배우나요?

AI에게 "여기 데이터 저장되게 해줘"라고 하면 AI는 되묻습니다. *"브라우저에 저장할까요, 서버 데이터베이스에 저장할까요?"* 이때 두 단어의 차이를 모르면 대화가 멈춥니다.

용어를 아는 것은 문법을 아는 것과 다릅니다. 여러분은 자동차를 만들 줄 몰라도 "엔진", "브레이크", "연비"라는 말로 정비사와 대화하죠. 같은 원리입니다.

## 서비스의 구조: 식당에 비유하기

웹 서비스는 식당과 닮았습니다.

| 식당 | 웹 서비스 | 용어 |
|---|---|---|
| 손님이 보는 홀, 메뉴판 | 사용자가 보는 화면 | **프론트엔드(Frontend)** |
| 주방 | 화면 뒤에서 실제 일을 처리하는 곳 | **백엔드(Backend)** |
| 냉장고, 창고 | 정보를 보관하는 곳 | **데이터베이스(DB)** |
| 홀↔주방 사이의 주문서 | 화면과 주방이 주고받는 약속 | **API** |
| 식당 건물 | 서비스가 실제로 돌아가는 컴퓨터 | **서버(Server)** |
| 개업 | 인터넷에 공개하는 것 | **배포(Deploy)** |

## 꼭 알아야 할 용어 20개

### 화면 쪽
1. **HTML** — 화면의 뼈대. 제목, 문단, 버튼이 "무엇인지" 정합니다.
2. **CSS** — 화면의 옷. 색, 크기, 배치를 정합니다.
3. **JavaScript** — 화면의 움직임. 버튼을 누르면 무슨 일이 일어나는지 정합니다.
4. **컴포넌트(Component)** — 재사용 가능한 화면 조각. "버튼", "카드", "헤더" 같은 것.
5. **반응형(Responsive)** — 폰에서도 PC에서도 예쁘게 보이는 것.

### 데이터 쪽
6. **데이터베이스** — 표(테이블) 형태로 정보를 오래 저장하는 곳.
7. **테이블 / 컬럼 / 로우** — 엑셀의 시트 / 열 / 행과 같습니다.
8. **CRUD** — 만들기(Create), 읽기(Read), 고치기(Update), 지우기(Delete). 모든 서비스의 기본 네 동작.
9. **인증(Auth)** — 로그인. "너 누구야?"를 확인하는 것.
10. **세션 / 토큰** — 로그인했다는 사실을 기억해두는 방법.

### 연결 쪽
11. **API** — 프로그램끼리 대화하는 창구. "날씨 API를 부른다" = 날씨 회사 서버에 물어본다.
12. **요청(Request) / 응답(Response)** — 물어보기 / 대답하기.
13. **JSON** — 프로그램끼리 데이터를 주고받을 때 쓰는 문서 형식. 사람이 읽을 수 있습니다.
14. **환경변수(.env)** — 비밀번호나 API 키처럼 코드에 직접 적으면 안 되는 값을 따로 보관하는 파일.

### 작업 쪽
15. **터미널** — 마우스 대신 글자로 컴퓨터에 명령하는 창. 3강에서 처음 열어봅니다.
16. **패키지** — 남이 만들어둔 코드 묶음. "설치한다"는 것은 이걸 가져오는 것.
17. **Git** — 작업 내용을 저장·되돌리기하는 도구. 5강.
18. **저장소(Repository)** — Git이 관리하는 프로젝트 폴더.
19. **배포** — 내 컴퓨터에만 있던 서비스를 인터넷에 올리는 것. 16강.
20. **버그 / 디버깅** — 잘못 동작하는 것 / 그 원인을 찾아 고치는 것. 15강.

## 따라하기: AI에게 설명 시켜보기

AI에게 이렇게 물어보세요.

> "API와 데이터베이스의 차이를 카페 사장님에게 설명하듯 알려줘. 각각 한 문단씩."

돌아온 설명을 읽고, **내 말로 다시 한 문장씩** 노트에 적어보세요. 내 말로 못 적으면 아직 모르는 것입니다. 20개 전부 할 필요는 없고, 오늘은 5개만 하세요.

## 오늘의 체크리스트

- [ ] 식당 비유로 프론트엔드 / 백엔드 / DB / API를 설명할 수 있다
- [ ] 용어 5개를 내 말로 적어봤다
- [ ] 1강에서 적은 "내 서비스 한 줄"에 화면(프론트)과 저장(DB)이 각각 어떤 게 필요할지 한 줄씩 상상해봤다

## 다음 강의
