## Claude Code는 어디에 있나요?

Claude Code는 별도 창이 아니라 **터미널 안에서** 돌아갑니다. 3강에서 연 VS Code의 터미널(`Ctrl + \``)에서 프로젝트 폴더로 이동하고 `claude`를 입력하면 시작됩니다.

```bash
cd my-first-app
claude
```

화면은 세 부분입니다.

```
┌──────────────────────────────────────────┐
│  대화 내용                                │  ← 내 요청과 Claude의 답, 변경 내용
│  (파일 변경 diff, 실행한 명령, 결과)         │
├──────────────────────────────────────────┤
│  > 여기에 입력                             │  ← 입력창
├──────────────────────────────────────────┤
│  모드 · 폴더 · 남은 맥락                    │  ← 상태 표시줄
└──────────────────────────────────────────┘
```

VS Code는 **결과를 눈으로 확인하는 곳**, Claude Code는 **일을 시키는 곳**입니다. 왼쪽 탐색기에서 파일이 생기고 바뀌는 게 실시간으로 보이니 두 개를 나란히 두세요.

## 외울 조작 7개

| 조작 | 하는 일 |
|---|---|
| 그냥 한국어로 입력 | 요청. "index.html 만들어줘" |
| `@파일이름` | 특정 파일을 콕 집어 말하기. 입력 중 자동완성됨 |
| `Shift + Tab` | 모드 전환: 매번 승인 → 자동 수락 → **계획 모드** |
| `Esc` | 진행 중인 작업 중단 |
| `/clear` | 대화를 비우고 새로 시작 (조각 하나 끝날 때마다) |
| `/compact` | 긴 대화를 요약해서 맥락 줄이기 |
| 이미지 붙여넣기 | 화면 캡처를 `Ctrl/Cmd + V`로 붙여넣으면 보고 작업함 |

이 중 **`@파일`** 과 **`/clear`** 가 결과 품질을 가장 크게 바꿉니다. "이 파일"보다 `@src/app/page.tsx`가 정확하고, 주제가 바뀌면 `/clear`로 새로 시작해야 엉뚱한 파일을 안 건드립니다.

## 승인 창 읽는 법

Claude Code는 파일을 고치거나 명령을 실행하기 전에 **무엇을 할지 보여주고 허락을 구합니다.**

```
● Edit src/app/page.tsx
  - <h1>Hello</h1>
  + <h1>안녕하세요</h1>

  Do you want to make this edit?
  ❯ 1. Yes
    2. Yes, and don't ask again for this file
    3. No, and tell Claude what to do differently
```

빨간(-) 줄이 사라지고 초록(+) 줄이 들어갑니다. 처음 2주는 **읽고 나서** Yes를 누르세요. 여기서 "요청한 것만 바꾸고 있는지" 보는 습관이 생깁니다. 이상하면 3번을 고르고 "그 파일 말고 이 파일만"이라고 말하면 됩니다.

명령 실행(`npm install` 등)도 같은 방식으로 물어봅니다. 안전한 명령은 "항상 허용"을 골라 귀찮음을 줄일 수 있습니다.

## 설정은 말로 바꿉니다

VS Code 글자 크기, 자동 저장, 탭 크기 같은 설정은 사실 `settings.json`이라는 파일입니다. 메뉴를 뒤질 필요 없이 Claude Code에게 말하면 됩니다.

> "VS Code 설정에서 글자 크기를 15로, 저장할 때 자동 정렬되게, 탭은 2칸으로 바꿔줘. settings.json을 직접 수정해줘."

Claude Code 자신의 설정도 마찬가지입니다. `/config`로 메뉴를 열어도 되고, "Claude Code 응답을 항상 한국어로 하게 설정해줘"라고 해도 됩니다.

## 있으면 좋은 것

- **VS Code용 Claude Code 확장**: 확장 탭에서 "Claude Code"를 설치하면 터미널 대신 사이드 패널에서 같은 대화를 할 수 있고, 변경 내용이 에디터 안에서 diff로 보입니다. 취향껏.
- **Prettier 확장**: 저장할 때 코드를 자동 정렬. Claude가 만든 코드와 여러분이 손댄 코드의 모양이 통일됩니다.
- **Error Lens 확장**: 에러를 해당 줄 옆에 바로 표시. 15강 디버깅 때 큰 도움이 됩니다.

세 개 다 Claude Code에게 "위 확장을 설치하는 명령어 알려줘"라고 하면 터미널 명령으로 한 번에 됩니다.

## 따라하기: 파일 하나 만들고 고쳐보기

1. Claude Code에: "index.html 파일을 만들고, 가운데에 '안녕하세요'라고 크게 나오게 해줘."
2. 승인 창을 **읽고** Yes → VS Code 탐색기에 `index.html`이 생겼는지 확인 → 클릭해서 내용 훑어보기
3. Claude Code에: "@index.html 글자색을 초록색으로 바꿔줘."
4. 승인 창에서 빨간 줄 / 초록 줄로 **정확히 그 부분만** 바뀌는지 확인 → Yes
5. 브라우저에서 파일을 열어 결과 확인
6. `/clear`

이 **요청 → 승인 창 읽기 → 파일 확인 → 브라우저 확인 → /clear** 순환이 앞으로 20일 동안 반복할 기본 동작입니다.

## 계획 모드 맛보기

`Shift + Tab`을 두 번 눌러 **계획 모드**로 바꾸고 이렇게 물어보세요.

> "이 index.html에 방문자 수를 세는 기능을 넣으려면 뭘 해야 해?"

계획 모드에서는 Claude가 파일을 **읽기만** 하고 방법을 설명합니다. 코드를 안 쓰니 안심하고 물어볼 수 있습니다. 큰 작업 전에 이 모드로 먼저 계획을 듣는 습관은 10강과 스킬 가이드에서 다시 다룹니다. 확인했으면 `Shift + Tab`으로 원래 모드로.

## 막혔을 때

- **`claude: command not found`**: 터미널을 닫았다 다시 열기. 그래도 안 되면 3강의 설치 명령을 다시.
- **로그인하라고 함**: 안내대로 브라우저에서 승인. `/login`으로 다시 시작할 수 있습니다.
- **응답이 영어로 옴**: "앞으로 한국어로 답해줘". 9강에서 규칙 파일로 고정합니다.
- **뭘 시켜야 할지 모르겠음**: `/help` 또는 그냥 "이 프로젝트에서 뭘 할 수 있어?"라고 물어보세요.
