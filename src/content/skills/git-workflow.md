## Git이 필요한 이유

AI 코딩 도구는 한 번에 여러 파일을 바꿉니다. 중간에 잘못되면 어디서 틀렸는지 모릅니다. Git이 있으면:

- **작동하는 시점으로 즉시 복구**
- **무엇이 바뀌었는지 한눈에 확인**
- **여러 시도를 병렬로 (브랜치)**

## 매일 쓰는 명령 4가지

```bash
git status          # 지금 뭐가 바뀌었는지
git diff            # 변경 내용 자세히 보기
git add -A          # 전체 변경을 스테이징
git commit -m "..."  # 저장
```

## 커밋 타이밍

> **작동하면 커밋.** 더 나아지기 전에 커밋.

- 페이지가 뜨면 커밋
- 버튼이 클릭되면 커밋
- AI가 뭔가 바꿨고 확인했으면 커밋

커밋 메시지는 짧고 한국어로:

```
홈 페이지 hero 이미지 추가
로그인 에러 메시지 수정
Supabase 연결 설정
```

## 잘못됐을 때 되돌리기

### 커밋 전에 발견
```bash
git checkout .        # 마지막 커밋 상태로 전체 복구
git checkout 파일이름  # 파일 하나만 복구
```

### 커밋 후에 발견
```bash
git log --oneline     # 커밋 목록 확인
git revert HEAD       # 마지막 커밋을 취소하는 새 커밋
```

> [!TIP]
> `git reset --hard`는 쓰지 마세요. push된 커밋을 되돌리면 팀에 피해가 갑니다. `git revert`가 안전합니다.

## 브랜치로 실험하기

큰 변경이나 확신이 없는 시도는 브랜치에서:

```bash
git checkout -b 새기능-시도    # 브랜치 만들고 이동
# ... 작업 ...
git checkout main              # 원래로 돌아오기 (시도 버림)
git merge 새기능-시도          # 성공했으면 합치기
```

## AI에게 Git 맡기기

Claude Code에게 커밋·push까지 맡길 수 있습니다.

> "작동 확인했어. 커밋하고 push해줘. 메시지는 '로그인 페이지 완성'."

단, push는 항상 확인 후:

> "push 전에 어떤 파일들이 포함되는지 먼저 보여줘."
