## 어떤 도구를 고르나요?

이 사이트의 강의는 **터미널에서 대화하며 파일을 직접 만들고 고치는 도구**를 기준으로 합니다. 대표적으로 Claude Code, Codex CLI, Gemini CLI 같은 것들이 있고 원리는 같습니다: 프로젝트 폴더에서 실행 → 한국어로 요청 → 파일 변경 → 확인.

브라우저 채팅창에 코드를 복사해 붙여넣는 방식과의 차이:

| | 채팅창 복붙 | 터미널형 도구 |
|---|---|---|
| 파일 수정 | 내가 직접 붙여넣기 | 도구가 직접 |
| 프로젝트 전체 파악 | 매번 설명해야 함 | 폴더를 읽고 시작 |
| 여러 파일 동시 수정 | 사실상 불가 | 가능 |
| 명령 실행 (설치, 빌드) | 내가 직접 | 도구가 실행하고 결과 확인 |

## 설치 순서

1. **Node.js LTS**가 있어야 합니다. `node -v`로 확인 (3강).
2. 도구의 공식 문서에서 **한 줄 설치 명령**을 복사해 터미널에 붙여넣습니다. 대부분 `npm install -g ...` 형태입니다.
3. 설치 후 터미널에 도구 이름을 입력하면 **로그인 안내**가 뜹니다. 브라우저가 열리고 계정으로 승인하면 끝.
4. **프로젝트 폴더 안에서** 실행하는 것이 중요합니다. 바탕화면에서 실행하면 바탕화면 전체를 프로젝트로 인식합니다.

```bash
cd my-service   # 프로젝트 폴더로 이동
[도구 이름]      # 실행
```

## 첫 요청: 안전한 것부터

처음엔 파일을 바꾸지 않는 요청으로 도구가 프로젝트를 제대로 읽는지 확인합니다.

> "이 프로젝트가 뭘 하는 프로젝트인지 파일들을 읽고 3줄로 설명해줘."

정확하게 설명하면 다음은 작은 변경:

> "README.md 맨 아래에 '마지막 수정: 오늘 날짜' 한 줄을 추가해줘."

도구가 **변경 내용을 보여주고 허락을 구하는지** 확인하세요. 대부분의 도구는 기본적으로 파일 수정 전에 승인을 요청합니다. 이 승인 단계를 끄는 옵션이 있지만, 5강의 Git 되돌리기에 익숙해지기 전까지는 켜두는 것을 권합니다.

## 알아두면 좋은 기본 조작

- **긴 작업 중단**: `Ctrl + C`
- **이전 대화 잊고 새로 시작**: 도구마다 `/clear`, `/new` 같은 명령이 있습니다. 주제가 바뀌면 새로 시작하는 게 결과가 좋습니다.
- **파일을 콕 집어 말하기**: 대부분 `@파일이름` 으로 특정 파일을 지목할 수 있습니다. "이 파일"보다 "@src/app/page.tsx"가 정확합니다.
- **화면 캡처 넣기**: 이미지를 붙여넣거나 경로를 알려주면 화면을 보고 작업합니다. "이 캡처처럼 만들어줘"가 됩니다.

## 흔한 설치 문제

- `command not found`: 터미널을 닫았다 다시 열기. 그래도 안 되면 `npm install -g` 시 권한 에러가 있었는지 확인.
- `EACCES permission denied`: macOS/Linux에서 npm 전역 설치 권한 문제. 에러 전문을 다른 AI 채팅에 붙여넣고 "sudo 없이 해결하는 법"을 물어보세요.
- 로그인 브라우저가 안 열림: 터미널에 출력된 URL을 직접 복사해 브라우저에 붙여넣기.
