## 루프가 없으면 생기는 일

AI 도구를 처음 쓰면 이렇게 됩니다. 요청 → 뭔가 됨 → 다른 요청 → 또 뭔가 됨 → 한 시간 뒤 "어라, 아까 되던 게 안 되네" → 원인을 모름 → 처음부터.

10강의 수직 슬라이싱이 "무엇을 만들지"라면, 이 루프는 "어떻게 하루를 보내는지"입니다.

## 다섯 단계

```
① 고르기  →  ② 요청  →  ③ 확인  →  ④ 커밋  ─┐
     ↑                       │               │
     └──── ⑤ 되돌리기 ◄──── 실패              └──► 다음 조각
```

### ① 고르기 (1분)
TODO.md에서 조각 하나. **딱 하나.** 두 개를 동시에 하고 싶어지면 그건 두 번 도는 겁니다.

### ② 요청 (3분)
7강 템플릿. 특히 "다른 파일은 건드리지 마"와 "확인 방법을 알려줘"를 빠뜨리지 않기.

### ③ 확인 (5분)
AI가 알려준 확인 방법을 **실제로** 해봅니다. 그리고 두 가지를 더:
- `git status`로 **바뀐 파일 목록**이 요청한 범위인지
- 이전에 되던 것 하나를 골라 **여전히 되는지** (회귀 확인)

### ④ 커밋 (1분)
됐으면 즉시. "조금 더 하고 커밋해야지"가 모든 사고의 시작입니다.

```bash
git add . && git commit -m "재료 입력: 중복 방지"
```

### ⑤ 되돌리기 (10초)
안 됐으면 고민하지 말고 `git checkout .`. 그리고 요청문을 고쳐 ②로. 세 번 실패하면 조각을 더 잘게 쪼개서 ①로.

## 루프를 짧게 유지하는 기술

- **한 대화 = 한 조각**: 조각이 끝나면 새 대화를 시작합니다. 이전 조각의 맥락이 섞이면 AI가 엉뚱한 파일을 건드립니다.
- **커밋 메시지는 조각 이름**: TODO.md의 한 줄을 그대로 쓰면 됩니다. 나중에 `git log`가 곧 작업 일지가 됩니다.
- **하루의 시작은 `git log --oneline -5`**: 어제 어디까지 했는지 30초면 파악됩니다.
- **하루의 끝은 push**: 노트북이 고장 나도 오늘 작업은 안전하게.

## 루프가 깨지는 신호

- 마지막 커밋이 1시간 이상 전 → 조각이 너무 큼
- `git status`에 파일이 10개 이상 → AI가 범위를 넘음. 되돌리고 "이 파일만"
- 같은 요청을 4번째 보내는 중 → 접근을 바꿔야 함. 15강의 "원인 후보 3개" 요청으로
- "일단 넘어가자"가 3번째 → 지금 15강 디버깅 시간
